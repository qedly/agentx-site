01 / Request

Start with useful work.

A specific request gives the agent a useful boundary. Start in a project-bound Slack channel or hand it over from your coding tool.

You start the task. Creating a GitHub issue does not start work.

Example request · docs project

Make the Copy button ready for its next use. Reset its label after copying, announce success accessibly, and preserve manual copy if clipboard access fails.

02 / Plan

Agree on the change before coding.

Quick gives you one implementation plan to approve. Read the scope and checks, request changes, or approve that version.

Required project checks stay required. Optional checks come from your project configuration.

03 / Code

Let the agent do the implementation.

The remote coding agent reads the repository, edits files and runs commands in the prepared workspace in your AWS account.

Your team configures the repository, environment, models and connections.

04 / Evidence

Inspect the evidence behind the result.

After checks pass, request the separate code and security AI reviews. Read their findings alongside the diff and named check output. Their code version matters.

A review finding is an AI recommendation. A named test result is evidence of that test, not proof of correctness.

Review packet Example contents
Code changes Diff and candidate reference
Checks Commands, output, environment and gaps
Code + security reviews Separate, read-only AI findings

If the code changes, dependent evidence needs to be refreshed.

05 / PR

Bring the work into your team’s review.

When the native workflow’s required checks and reviews qualify the candidate, request draft PRs. GitHub remains the source for comments, CI and merge state.

A task with multiple required PRs waits for all of them to be observed merged.

06 / Feedback

Continue through review, with your approval.

Rovara Code gathers PR comments, groups related feedback and proposes fixes. Inspect the details, approve selected changes, or ask for a different approach.

Feedback creates a proposal. It does not silently authorize another coding run.

PR feedback review Example proposal
“Keep keyboard focus on the Copy button.”

Proposed response
Use a polite status announcement. Keep focus unchanged. Check keyboard and clipboard failure behavior.

Your decision → approved fixes → fresh checks and reviews.
