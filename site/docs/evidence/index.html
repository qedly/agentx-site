Three different layers

Task checks

The verification extension reruns usable checks when the coding session finishes and compares before/after where possible. It can produce checks.json.

Publication checks

PR publication prepares the candidate and runs readiness checks. Configured CodeBuild gates produce additional evidence.

Repository CI

Your repository’s checks and merge rules remain authoritative for its normal review process.

A passing task report does not establish that all publication checks or repository CI ran on the same candidate.

Interpret the result

Result What it means What to inspect
Passed The named command passed during this run. Command, output, environment, coverage.
Regression It passed before and fails now. Before/after output and the patch.
Already failing It failed before and still fails. Whether the requested change addresses it.
No baseline There is no earlier result for comparison. The current outcome; no invented prior pass.
Not verified / not run The required observation is missing. Reason and the next check needed.

A regression gets at most one extra coding attempt. Remaining failures stay visible. Checks provide bounded evidence; they do not prove all code is correct.

Constructed example / not runtime proof

Inspect a CSV task packet.

This example explains what a reviewer should look for. It is not output from an observed AgentX run and is not a downloadable checks.json schema.

Code diff — proposed empty-record handling 
--- src/export/csv.ts
+++ src/export/csv.ts
- return records.map(formatRow).join("\n");
+ return records
+   .filter(record => record != null)
+   .map(formatRow)
+   .join("\n");

Review whether skipping null records is the intended behavior and whether legitimate empty field values are preserved.

Test evidence — before, after, and unavailable
Check Before After
Existing CSV tests Passed Passed
New null-record test No baseline Passed
Database integration Unavailable Not run

Illustrative outcomes only. No pass count, timing, exit code, or raw output is invented. A real packet will link the command, environment, output, and candidate.

Review questions — what does the evidence cover?
  • Which commands actually ran, and where?
  • Which had an earlier result?
  • Did any passing check regress?
  • Which checks were skipped, unavailable, or not rerun?
  • Does the evidence apply to the candidate being reviewed?

In this scenario, the database integration is unverified. Request it before merging if it is required for this change.

Publication behavior

A reporting-enabled new PR can be opened as a draft with failing checks. Older compatible publication paths can refuse a new PR when readiness fails. Appending or syncing an existing PR still refuses a failing readiness check.

CodeBuild results provide evidence, not an automatic publication gate. A draft PR alone is not proof that the change is ready. Your team decides what gets merged.
