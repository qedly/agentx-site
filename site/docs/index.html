01 / Overview

A coding agent with a reviewable handoff.

Rovara is the public display brand for AgentX. The underlying project, CLI command, configuration, and evidence identifiers remain agentx / AgentX.

Start a task from Slack or hand it over from Claude Code, Codex, or Cursor through MCP. The remote coding agent works in a persistent workspace in your AWS account. Inspect the returned code and available test and check evidence. Your team decides what gets merged.

Public release in preparation

The product source is currently private and there is no published installer. These pages explain the inspected implementation and setup requirements. A public command and complete version-matched install path will be added with the release.

02 / Administrator setup

Start with the deployment guide.

Requirement What your team needs
AWS A dedicated account, administrator access for first setup, and capacity in us-east-1. The installer checks worker capacity and two free Elastic IPs.
Node.js 22.19.0 or newer within the 22.x series, below 23. If your CloudShell session runs Node 20, upgrade it before setup.
GitHub Permission to create a GitHub App and grant it access to the selected repositories.
Slack Permission to create and install a Slack app. Your workspace administrator may need to approve it.
Model access Amazon Bedrock is the default. Anthropic, OpenAI, or OpenRouter can also be configured; rates and availability depend on your provider.

Source-checkout installation currently builds release assets locally and needs images you build and push yourself. Follow the authorized checkout’s docs/install.md and docs/releases.md; the public release path is not available yet.

First setup uses administrator credentials. Later operations use the narrower operator role created by setup. The documented account boundary matters when choosing where to deploy.

03 / Developer handoff

Use Slack or your coding tool.

In Slack

Use a configured project channel and mention the app with a concrete task. Keep follow-ups in the task’s thread so the workspace can be resumed. Ask to inspect progress or request a pull request when ready.

From Claude Code, Codex, or Cursor

The MCP server exposes developer tools for allowed projects and remote tasks: start, check, continue, share, cancel, close, and request a pull request. Developer sign-in and project access are prerequisites.

After the CLI has been built or installed from an authorized source, its MCP setup entry is: 

agentx mcp install

This configures the MCP integration; it does not download a public package or deploy the AWS environment. Use the CLI’s version-matched instructions for your coding tool and developer sign-in.

04 / Check evidence

What ran. What failed. What is missing.

The worker installs a verification extension in new and resumed coding sessions. At the end of a completed turn, it runs project-configured checks when present, or recognized test commands from the session. It can compare against an available before-change baseline and give the agent one extra attempt on regression.

The worker stores a checks.json report, with command labels, outcomes, and output. Task results can carry a compact report with output tails. Full output and compact task output can therefore differ in length.

Evidence How to read it
Passed command The named command passed in the reported run. Check whether its coverage is relevant.
Regression A check known to pass before the change failed after it. An unresolved regression remains visible after the extra attempt.
Failure / timeout Inspect the named command, output, and baseline. A failure with no baseline is not automatically a new regression.
Not verified No usable checks, a stop, an error, or unrerun checks can prevent a verified report. Read the reported reason.

At pull request publication

Publication runs registered readiness checks and sends the candidate commit to configured CodeBuild checks. The reporting-enabled path can open a draft PR with failing checks; compatible older paths without reporting can refuse publication on readiness failure.

Checks are reported evidence. They do not guarantee correctness, establish that every task is verified, or prove every check ran on the exact final PR commit. CodeBuild results do not automatically block PR creation. Your repository’s merge rules and human review remain in force.

05 / Task lifecycle

Continue, cancel, and close deliberately.

A follow-up resumes the task’s workspace and conversation. Idle workers can stop while encrypted workspace storage remains. Retained volumes continue to incur storage charges.

Cancellation stops task work; workspace closure is a separate lifecycle operation. Inspect the task state and the version-matched operator instructions before cleanup. Do not treat stopping a worker as removing the complete environment.

For installation recovery, updates, logs, and teardown, use the operator documentation matching the installed source commit or release. These public pages do not claim a clean-room install or live AWS acceptance run has completed.

06 / Architecture

The infrastructure you operate.

Slack ingress queues requests for the Fargate orchestrator. The control plane authorizes project access and manages task state; EC2 workers execute the coding sessions in prepared project workspaces. Encrypted EBS retains workspace files across idle compute stops.

External integrations keep their own boundaries: model calls go to the configured provider, repository operations use GitHub, and team messages use Slack.

07 / Connections

Entry points and project context.

Slack and developer MCP are task entry points. They let people start and follow remote work. Claude Code, Codex, and Cursor use the MCP interface to manage tasks.

Linear, Jira, Asana, and remote MCP connectors add project context and configured tools. They are separately configured for a project and do not grant unrestricted access to every service or workspace.

Connector access depends on provider authorization and project configuration. Review the current source’s connector guide for scopes, teams, and supported authentication before connecting a real service.

08 / Cost model

An estimate, not a fixed price.

The installer shows a resource plan and a monthly estimate before creating the environment. Your team pays AWS and model charges and can configure a monthly budget alert.

About $211/month in one illustrative workload.

us-east-1; September 2026 price inputs; default Bedrock models; 1,000 turns, 100 worker sessions, 60 worker instance-hours, and 10 retained workspaces. Derived from the installer’s pricing formula, not a quote. NAT data processing and some usage-dependent charges are excluded.

Two NAT gateways and the always-on Slack service create a baseline cost. Worker hours, retained EBS storage, model use, and data transfer change the total. OpenRouter model cost is not included in the estimate because the estimator has no price on file.

A budget alert is a notification, not a spending cap. Stopping idle workers reduces compute use; it does not stop retained-storage or always-on-service charges.

09 / Trust boundaries

Review the account and credential scope.

  • Each task has an isolated EC2 worker and encrypted EBS workspace.
  • AWS accounts provide the documented security boundary. Environments sharing an account are not security boundaries from each other.
  • The coding worker reads and edits checked-out code and runs shell commands. Treat its output as untrusted until review.
  • Installer secrets use hidden prompts, files, or environment variables and are stored in AWS Secrets Manager, rather than local AgentX settings.
  • GitHub permissions, identity, cloud guardrails, CI, and human merge authority remain part of your operating model.

These are implementation and ownership facts, not a security certification, penetration test, or compliance attestation.

10 / Evaluation

Published evidence needs a method.

Evaluation tooling and internal pilot material exist. No public solve rate, model comparison, customer adoption, time-saved, or quality-improvement claim is made here.

A credible public demo should show a reproducible task from request through code, checks, and human review using a test repository. Private Slack messages and run records need consent and redaction before publication.

Passing repository tests mean those tests passed in their CI environment. They do not establish a successful live AWS install, a customer outcome, or the correctness of all code an agent produces.

11 / Release and license

What becomes available at launch.

Current status: no public product repository, published release, or npm package. The current code license is FSL-1.1-ALv2, source-available rather than OSI open source; each release converts to Apache 2.0 two years after it ships.

The public self-hosted launch needs source and license publication, versioned release artifacts, reproducible installation, a supported first-task path, and operator, security, and contribution guidance. Until those are available, the deployment guide is preparation rather than a working public install.

The published release must state its supported region, Node range, worker images, model configuration, upgrade path, and removal procedure. The source snapshot reviewed for these pages lists us-east-1 and Node >=22.19.0 <23.
